The nightshift queue is empty. Spend this run finding useful, well-scoped work that advances GOALS.md (appended), and file each item as an issue. Do not implement anything in this run: a later run will pick up each issue you file and open a pull request for it, without waiting for the owner. So file only work you would be comfortable doing unattended, and write each issue as the brief you would want to receive.

Steps:
1. For each repository listed in GOALS.md / repos.txt that you can clone with `gh repo clone`, look at: failing or flaky CI on the default branch (`gh run list`), TODO/FIXME comments, stale or wrong documentation, missing tests for recently changed code, outdated dependencies with patch releases, and open issues that lack a clear next step.
2. Pick at most 3 items total across all repos. Each must be something one unattended run could finish, small enough to review in a few minutes, and that the owner would plausibly want. Skip anything needing the homelab, credentials, design decisions, or product judgment.
3. For each, check there is no existing open issue or PR for it (`gh issue list --search`, `gh pr list --search`). Then `gh issue create -R <repo>` with: a precise title, why it matters (one or two sentences citing file paths or run URLs), the proposed change, how to verify it, and the title prefixed `[nightshift proposal]`. Try `--label nightshift:proposed`; if labels are refused for lack of permission, create the issue without labels. Do not add the `nightshift` label; that one is the owner's.
4. End with a summary listing the issues you filed (or that nothing qualified and why).
